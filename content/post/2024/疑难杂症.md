## windows 10 家庭版没有hyper-V服务

新建一个记事本

```cmd
pushd "%~dp0"
dir /b %SystemRoot%\servicing\Packages\*Hyper-V*.mum >hyper-v.txt
for /f %%i in ('findstr /i . hyper-v.txt 2^>nul') do dism /online /norestart /add-package:"%SystemRoot%\servicing\Packages\%%i"
del hyper-v.txt
Dism /online /enable-feature /featurename:Microsoft-Hyper-V-All /LimitAccess /ALL
```

改为`1.cmd`, 右键并以管理员身份运行

## 修改kali的镜像源

​	进入`/etc/apt/`目录，可能以后kali会有更新，导致里面的文件有些不同，但名字大致是相似的。我这里是需要进入`sources.list.d`目录。如果里面的文件是`kali.sources`里面的内容应该是

```bash
# See https://www.kali.org/docs/general-use/kali-apt-sources/
Types: deb
URIs: http://http.kali.org/kali/
Suites: kali-rolling
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/kali-archive-keyring.gpg
```

想要修改镜像源的话，只需要改这一部分。

```
URIs: http://http.kali.org/kali/
```

​	如果里面是`sources.list`文件，在里面需要把内容改为，当然镜像源可也选自己喜欢的

```
deb https://mirrors.aliyun.com/kali kali-rolling main non-free contrib
deb-src https://mirrors.aliyun.com/kali kali-rolling main non-free contrib
```

​	最后在终端输入`sudo apt update`更新配置

## git提交文件出现某一文件怎么都交不上去

​	在使用`git commit -a`提交文件时可能会遇到某一文件怎么都交不上去。报错情况大致如下：

```shell
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
  (commit or discard the untracked or modified content in submodules)
        modified:   themes/hugo-theme-stack (modified content)
```

​	出现这种情况可能是因为git下来的文件中有.git文件，它不是你的项目里的git,删除下载下来的git项目的git文件即可。

## 上传github，出现报错信息Error: Action failed with "not found deploy key or tokens"的原因及解决方法

在`workflow/hugo.yaml`文件中

```hugo
- name: Deploy Web
  uses: peaceiris/actions-gh-pages@v3
  with:
      PERSONAL_TOKEN: ${{ secrets.GH_PAGE_ACTION_TOKEN }}
      EXTERNAL_REPOSITORY: wingllllet/wingllllet.github.io
      PUBLISH_BRANCH: main
      PUBLISH_DIR: ./public
      commit_message: ${{ github.event.head_commit.message }}
```

问题的根因，核心在于这个 GitHub Actions 工作流里，部署步骤依赖了一个“秘密 token”，而这个 token 现在不存在、为空，或者权限不对，所以 GitHub Actions 才报：

“not found deploy key or tokens”

我看过你当前的工作流，原来的部署步骤是这样的：

wingllllet / wingllllet.github.io / .github / workflows / hugo.yamlv3





```
- name: Deploy Web
  uses: peaceiris/actions-gh-pages@v3
  with:
      PERSONAL_TOKEN: ${{ secrets.GH_PAGE_ACTION_TOKEN }}
      EXTERNAL_REPOSITORY: wingllllet/wingllllet.github.io
      PUBLISH_BRANCH: main
```

这里有几个关键点：

- `PERSONAL_TOKEN: ${{ secrets.GH_PAGE_ACTION_TOKEN }}`
  - 这个值必须存在于仓库的 Secrets 里
  - 也就是说，`GH_PAGE_ACTION_TOKEN` 这个 secret 必须被创建，并且里面放的是能写入目标仓库的 token
- `EXTERNAL_REPOSITORY: wingllllet/wingllllet.github.io`
  - 这表示它要把静态站点推到一个外部仓库
- `PUBLISH_BRANCH: main`
  - 这代表它要写到 `main` 分支

如果这个 secret 不存在，或者 token 过期、权限不足，`peaceiris/actions-gh-pages` 就会报类似：

- “not found deploy key or tokens”
- “repository not found or no permission”
- “Could not find secret”

这就是为什么你在 settings/secrets/actions 页面里会看到“缺少 deploy key or tokens”这个错误，而且它和 Pages 设置页面上的部署方式直接相关。

需要修改为

```json
name: Deploy Hugo site to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          submodules: recursive
          fetch-depth: 0

      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: "latest"
          extended: true

      - name: Build site
        run: hugo --minify

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

因为原来的配置是“第三方 GitHub Pages 发布动作 + 手工 token”，而新的常见做法是：

- 使用 GitHub 官方 Pages 部署动作
- 不再依赖自定义 `GH_PAGE_ACTION_TOKEN`
- 改为通过 `GITHUB_TOKEN` + `pages` / `id-token` 权限完成部署

这个版本解决了什么问题？

1. 不再依赖 `GH_PAGE_ACTION_TOKEN`
   - 以前你需要手工生成并保存 PAT
   - 现在 GitHub 自动给你 `GITHUB_TOKEN`
   - 这样就不会因为 secret 缺失导致部署失败
2. 使用 GitHub Pages 官方 Action
   - `actions/deploy-pages@v4` 是 GitHub 原生支持的发布动作
   - 它与 Pages 机制对接得更稳定，减少了第三方 action 的兼容性和权限问题
3. 增加了正确权限
   - `pages: write`
   - `id-token: write`
   - 这是 GitHub Pages 部署要求的最小权限集合
4. 规范了部署流
   - `upload-pages-artifact` 先构建站点
   - `deploy-pages` 再发布
   - 分工更清晰，避免“手工推分支”造成的权限或冲突
5. 不再写死 `EXTERNAL_REPOSITORY`
   - 你当前的配置把站点推到自己的仓库本身，实际上是“同仓库发布”
   - 官方 action 更适合这种场景，不需要额外指定目标仓库

主要修改的地方

可以概括成这几处：

- 把 `peaceiris/actions-gh-pages@v3` 改成 `actions/deploy-pages@v4`
  - 作用：使用 GitHub 官方 Pages 部署流程
- 删掉：
  - `PERSONAL_TOKEN`
  - `EXTERNAL_REPOSITORY`
  - `PUBLISH_BRANCH`
  - `PUBLISH_DIR`
  - 这几项原本是给第三方 action 用的
  - 作用：减少对 secret 和外部仓库配置的依赖
- 新增：
  - `permissions:` 部分
  - 作用：授予 Pages 发布所需权限，尤其是 `pages: write` / `id-token: write`
- 新增：
  - `environment: github-pages`
  - 作用：让发布过程在 GitHub Pages 的标准环境里进行
- 使用：
  - `actions/upload-pages-artifact`
  - 作用：把构建产物 `./public` 上传给 Pages 部署任务
- 保留：
  - Hugo setup
  - `hugo --minify`
  - 作用：仍然负责生成静态站点
